让你常用的 agent 来下拓扑五子棋：可以挑战内置 AI，也可以邀请两位 agent 分执黑白。棋盘之外，悬浮气泡呈现棋手的内心旁白：它注意到了什么，对这一手有什么反应，又有什么打算。表达的时机与方式由棋手决定。

棋手随想供观众阅读，对手和解说员不会收到。解说默认关闭，需要时再邀请一位 agent 根据棋盘独立点评。

> 当前为本地预览，GitHub 的 `arena` 发行分支尚未发布。下方启动提示已包含分支下载流程；发布前可复用已有预览目录，远端缺少分支时 agent 会明确告知你。

## 1. 让一个 agent 打开对弈室

在这台电脑上打开任意一个能读取本地文件、运行命令的 agent，把下面这段话发给它。下载代码、准备环境和启动服务都交给它处理。

```text
请帮我安装并打开“拓扑五子棋 Agent 对弈室”。从 https://github.com/YinkaiYu/topology-gomoku 的 arena 分支获取代码，放到独立的本地目录；若本机已有可用的 Arena 目录，直接复用。不要覆盖已有文件，也不要用 main/dev 代替缺失的 arena 分支。

取得代码后，读取 arena/skills/topology-gomoku-arena/SKILL.md，按主持流程准备运行环境、启动服务并打开浏览器。告诉我代码所在目录和观战地址。如果用了非默认地址，按 README 第 2 步给我一段填好实际地址的接入提示。
```

启动后，你会看到对弈室首页。以后继续使用时，告诉这个 agent“请打开之前的拓扑五子棋对弈室”，它可以复用已有服务。

所有参赛 agent 都应运行在同一台电脑，能访问这份代码和本地服务。普通网页聊天窗口不适用于这一流程。模型仍使用各自客户端的账户；对弈室不需要模型 API key，云模型仍需联网。

## 2. 提前接入参赛客户端

在准备参赛的每个客户端里发送下面这段话。同一个客户端已接入该对弈室时，无需每局重复配置。

```text
请为当前客户端配置“拓扑五子棋 Agent 对弈室”的 MCP 连接。服务已在这台电脑上启动，默认地址为 http://127.0.0.1:4318；如果我提供了其他地址，以那个地址为准。

访问服务的 /api/health，确认 service 为 topology-gomoku-arena，从 workspacePath 找到本地仓库。读取其中 arena/skills/topology-gomoku-arena/SKILL.md 的“MCP 接入”部分，为当前客户端配置并检查连接。本次只完成接入，等待我另发棋局邀请；需要重载或重启客户端时，告诉我具体步骤。
```

**如果需要重载或重启客户端，先按 agent 给出的步骤完成，再继续下一步。** 这一步不需要棋局或席位凭证。服务使用非默认地址时，直接复制启动 agent 给你的接入提示。

负责启动的 agent 和两位棋手可以使用任意支持的客户端组合，包括同一种客户端的两个独立会话。只需下载一份游戏、运行一个服务，各客户端分别配置连接；同一客户端的不同项目也要确认能加载该连接。仅负责启动的 agent 无需配置下棋工具。准备邀请解说员时，也提前为它接入。

## 3. 创建棋局，邀请棋手

在浏览器选择关卡和对弈方式，按喜好调整棋盘尺寸、双方名称与头像，然后创建棋局。从棋局设置中复制黑方邀请发给黑方会话、白方邀请发给白方会话。

邀请包含本局地址、席位凭证、操作 Skill 和对应角色提示词的本地路径。agent 自行读取文件、加入席位；你不需要另找配置文件或手写参数。双方就绪后，在浏览器设置中点击开始。

选择“Agent 与内置 AI”时，只需要邀请黑方。想听解说时，再从设置里复制解说邀请；可以邀请第三个 agent，也可以让负责启动的 agent 兼任。

## MCP、Skill 和插件，需要装哪些？

| 名称 | 在这里做什么 | 你需要操作吗？ |
| --- | --- | --- |
| MCP | 让棋手调用读棋盘、落子、随想和等待等工具 | 把接入提示发给对应 agent，按需重载客户端 |
| Skill | 说明接入、参赛、等待和恢复流程 | 提示里有本地文件路径，直接读取即可，无需安装 |
| Plugin | 可打包客户端扩展 | 本产品不要求额外安装插件 |
| CLI | 通过本地命令完成相同的棋局操作 | 留给明确选择这种方式的用户，不自动替代 MCP |

DeepSeek Harness 自带的 MCP client 在其配置中以插件条目表示，这不等于需要再安装一个“拓扑五子棋插件”。

## 看棋、复盘与继续

随想气泡从底部出现，旧消息向上移动。设置面板中可以暂停、继续、邀请解说、查看时间线和导出棋谱。棋手可以自行认输，或提出和棋由对方接受；终局保留棋谱与随想，可以回看。记录带有时间，支持结束、删除单局和清空已结束记录。

关闭负责启动的 agent 会话，不会关闭棋局服务。如果一位棋手提前结束了任务，在它原来的会话中发：

```text
请继续刚才的拓扑五子棋比赛，沿用原席位。按邀请里操作 Skill 的恢复流程，读取最新局面后继续。
```

MCP 不能自动唤醒已经结束的会话。原会话找不到时，可从浏览器重新复制该席位的入席邀请，交给接替的会话恢复；已有身份和棋局会保留。

## 亲自调整棋手提示

棋手如何表达，集中在 [player.md](arena/prompts/player.md)；解说方式在 [commentator.md](arena/prompts/commentator.md)。启动与接入提示就在本 README 的第 1、2 步；[入席邀请](arena/prompts/invitation.md)只传递本局信息与文件入口，[操作 Skill](arena/skills/topology-gomoku-arena/SKILL.md)负责实际流程。

完整清单和生效方式见[提示词文件索引](docs/development/arena.md#提示词文件)。修改后让 agent 重新读取相应文件；已读入会话的旧内容不会自动更新。

## 关于这个版本

对弈室面向横屏电脑浏览器，沿用[拓扑五子棋](https://github.com/YinkaiYu/topology-gomoku/tree/main)的视觉与规则：平面、圆柱、环面、莫比乌斯带、克莱因瓶、实射影平面和球面。棋盘尺寸可设为 5–19，球面使用正方形棋盘。

`arena` 是独立长期发行渠道，对局服务、MCP、CLI、Skill 和观战界面只在这里维护，从 `dev` 同步共享游戏更新。运行记录、邀请凭证和棋谱保存在本机，不提交到仓库。

开发、手动启动和验收说明见[开发文档](docs/development/arena.md)。源码使用 MIT License，内嵌字体和头像标识保留各自许可。当前提供五种客户端配置片段；协议已测试，尚未逐一验证五种客户端的完整对弈会话。
