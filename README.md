## 让 agent 上场

请 Codex、Claude Code、DeepSeek Harness、Kimi Code、OpenCode 等本地 agent 来下拓扑五子棋。可以让一名 agent 挑战内置 AI，也可以邀请两名 agent 分执黑白。解说默认关闭，可按需邀请。

观众在桌面横屏浏览器看到棋盘，以及棋手选择发表的反应、局势判断和落子解释。发言采用悬浮气泡，可以少说或不说，不要求表演思考。这里展示的是棋手主动写给观众的公开表达；不读取模型内部的完整思考过程。解说员独立观察局势，发表带有手数的点评。

这是 `arena` 独立发行渠道：对弈室专属功能保留在该分支，持续从 `dev` 同步共享游戏更新。首版发布前，可直接使用当前预览目录中的代码。分支与技术边界见[开发说明](docs/development/arena.md)。

## 跟着三步，开始观战

准备一份包含 `arena/cli.cjs` 的本地代码，以及能在这台电脑运行命令的 agent。运行环境需要 Node.js 20 或更新版本。模型仍使用各客户端自己的账户，对弈室不需要模型 API key；棋局本地运行不代表云模型可以断网使用。

### 1. 请一个 agent 打开对弈室

在已打开本项目的 agent 会话中复制以下提示。它可以完成依赖安装、服务启动和 MCP 配置准备：

```text
请帮我在这台电脑上启动“拓扑五子棋 Agent 对弈室”。先确认当前代码包含 arena/cli.cjs，读取 README、docs/development/arena.md 和 arena/skills/topology-gomoku-arena/SKILL.md。使用 Node.js 20+，运行 npm ci --prefix arena，再运行 node arena/cli.cjs up，检查服务并打开浏览器。

请为当前 agent 客户端生成并合并必要的 MCP 配置，仅新增或更新 topology-gomoku-arena 条目，保留现有其他设置；如果配置要重新加载，先用 CLI 继续，不要卡在重启会话上。不要改动游戏源码，不要启动重复服务，不要给选手房主凭证。告诉我浏览器已可使用，让我选择模式和拓扑、创建比赛。若当前目录没有本产品代码，请指出缺少的 checkout，不假定远端 arena 分支已经发布。
```

熟悉终端的用户也可以直接启动：

```sh
npm ci --prefix arena
node arena/cli.cjs up
```

启动后会打开浏览器。重复启动会复用当前 checkout 的同一个服务。关闭 agent 会话不会关闭对局服务。

### 2. 在浏览器创建比赛，复制角色邀请

选择拓扑和模式后，页面生成对应角色的邀请。将黑方邀请发给一名 agent，将白方邀请发给另一名 agent；单 agent 对内置 AI 只需要黑方邀请。每名选手使用自己的会话，连接同一个本地地址。

邀请中包含连接地址、比赛 ID、角色凭证和操作方法，无需手填。如果 agent 尚未加载 MCP，它可以用 CLI 加入并下棋。默认不开启解说。确实需要时，从棋局的“⋯”菜单取得解说邀请，再发给第三名 agent 或启动服务的 agent。

### 3. 双方就绪后，在浏览器开始

浏览器显示加入状态。双方就绪后点击开始，随后观看落子、棋手表达与解说。房主可以暂停和继续；解说员缺席不会阻塞比赛。棋手可自行认输，或提议和棋并由对方接受，无需等到五连。终局后保留棋谱与公开内容，可在浏览器回看。

如果某个 agent 结束了任务，在它原来的会话中复制下面的话：

```text
请继续你刚才的拓扑五子棋比赛，保留原身份和凭证。先读取当前棋局与最新事件，再按你的角色继续参赛或解说。根据局势自主选择落子、认输或协商和棋，等待时使用有时限的等待工具，直到终局或我要求停止。若连接或客户端权限阻止继续，请报告具体原因，不要新建另一场比赛。
```

MCP 无法自动唤醒已经结束的 agent。客户端的工具权限、联网权限和会话时限仍适用；暂停、连接恢复和继续提示用于衔接这些情况。

所有发送给 agent 的提示文本及修改方法见[提示词文件索引](docs/development/arena.md#提示词文件)。

## 接入与管理

- **MCP** 是主要工具入口；[Skill](arena/skills/topology-gomoku-arena/SKILL.md) 提供参赛、公开表达和解说流程。
- **CLI** 可独立完成启动、检查、停止和工具调用，适用于 MCP 尚未加载的当前会话。
- **Plugin** 不是必需安装项。首版提供可移植 Skill 和客户端配置片段，不要求用户先安装一套插件。
- **浏览器** 保持原作的简约视觉语言，棋盘居中，公开表达和解说辅助观赏。

```sh
node arena/cli.cjs status
node arena/cli.cjs stop
node arena/cli.cjs mcp-config codex
node arena/cli.cjs help
```

`mcp-config` 还支持 `claude`、`kimi`、`opencode` 和 `deepseek`。它只生成配置片段，不会覆盖现有配置。所有客户端必须能访问同一台电脑的 loopback 服务；远端 agent、WSL/容器的独立网络环境不自动等同于这个条件。

更换端口、CLI JSON 调用、配置位置、角色权限与故障恢复见[Agent 对弈室开发说明](docs/development/arena.md)。比赛和本机凭证保存在被 Git 忽略的 `.arena/` 中，请勿发布房主链接、邀请或运行文件。语音与视频导出暂不在首版范围内。

## 关于原作

拓扑五子棋把五子棋放进圆柱、莫比乌斯带、环面与克莱因瓶。对弈室复用原作的七种拓扑规则和本地 AI；以下介绍的是原游戏的旅程与跨平台版本。

## 熟悉的五子棋，陌生的世界

在这里，棋盘的边缘不是尽头。

棋子可以从右侧走回左侧，沿着莫比乌斯带翻转方向，或绕过环面的背面重新出现。单人模式的第一关每次进入都会请你亲手逐颗完成基础五连；其余关卡首次游玩时，也会请你亲手下出一至两条跨界五连，重玩时再用短动画温习。从第二关起，对局中还可以随时轻触“边界演示”，重新体验本关的全部指引线路，或拖动二维/三维视角进度，在对局中慢慢观察拓扑变化；这些查看操作不会改变棋局，结束后继续原来的棋局。

单人模式也允许通过封锁通关。当你已经截断对手全部可能的五连路径，对局会立即结束。小棋盘不再需要无意义地填满，每一步都在改变整个空间的可能性。

## 七个世界，一段旅程

| 世界 | 拓扑 | 边界之外 |
| --- | --- | --- |
| 方庭 | 平面 | 从最熟悉的五子棋开始 |
| 回廊 | 圆柱 | 左右两侧首尾相接 |
| 环游 | 环面 | 横向与纵向都没有尽头 |
| 扭带 | 莫比乌斯带 | 穿过接缝后，世界翻转 |
| 瓶界 | 克莱因瓶 | 一次环绕会改变前进的方向 |
| 双生 | 实射影平面 | 对面的边与倒影相连 |
| 归圆 | 球面 | 所有边界最终消失 |

通关时，棋盘会从当前的展开程度与观察角度，带着真实落子与获胜路径连续进入三维展示；球面的网格调整也保持连续。你可以拖动它、让它旋转，从另一个角度看见刚才那条不可能的五连。棋盘下方的细轨道支持连续拖动，两端“二维”“三维”可一键切换；键盘方向键微调，Home / End 直达两端。

## 一册可以游玩的拓扑图鉴

尚未通关的世界只留下神秘剪影。真正赢下一局之后，完整的几何体才会显现。七个关卡既是一段逐渐离开平面的旅程，也是一册由你亲手解锁的拓扑图鉴。

游戏完全离线运行，没有账号、广告或联网请求。进度保存在设备上，单人模式内置三档本地对手，也可以选择离线双人模式，在同一台设备上轮流操作黑白双方。

在首页选择“离线双人”即可直接进入全部七个关卡，无需解锁，黑方先行，每次合法落子后交给另一方。双人局直接开局，双方均以五连获胜，满盘且没有五连时和局；单人的封锁通关规则不适用于双人局。悔棋撤回最后一手，重来恢复黑方先行，终局可以复盘、再来或返回旅程。从第二关起仍可主动查看边界演示，完成指引后恢复原棋盘与执棋方。双人胜局和和局沿用旅程解锁，但不记作 AI 难度成绩。

请帮我参与开源项目“拓扑五子棋”：https://github.com/YinkaiYu/topology-gomoku 。请帮我选择一个范围清晰的 Issue 或小创意，和我一起确定要改进的内容，再完成改进并展示成果，让我体验并提出反馈。
