# 1.39.0 发布说明

本轮核心稳定版本为 `1.39.0`，沿 `dev → main → 五个发行分支` 传播；分支接收版本不代表已上传、通过平台审核或线上生效。各渠道仍须完成自己的适配与宿主验收。

## 产品变化

- 对局中可用滑块连续、可逆地控制二维／三维视角，两端按钮可快速切换；观察视角不改变棋局或回合。
- 转换期间锁定落子并延后 AI，避免按下与松手跨越动画造成误操作；取消、失焦和离开关卡后正确释放交互状态。
- 终局从当前形态、旋转与弹性连续开始，修复球面参数化交接跳变；自动终局展示与滑块同步。
- 控件沿用设置页的液态玻璃交互，使用轻量图标按钮与按压折射；引导期间保留占位，终局工具顺序和三排对齐统一。

## 协作与交付

- 新增 [PR 审查与协作指南](../development/pr-review.md)，将证据化反馈、复审、接手修复、署名与任务清理边界接入贡献指南、Agent 规则和 PR 模板。
- 设计原则与回归矩阵见 [视觉设计语言](../design/visual-language.md) 和 [视觉 QA](../design/qa.md)。
- 个人网站与知乎发行流程进入共享基线；部署到外部网站、CloudBase 或平台审核仍是独立动作。

## 渠道门禁

小红书、Bilibili、微信、个人网站与知乎都必须继承同一个稳定 `main`，不能只修改版本号而跳过功能对齐。平台构建、原生交互、宿主预览与真机结果在各自发行记录中补充；未经执行的项目保持未验证，不以共享 H5 的通过结果替代。

尤其是微信原生 Canvas：新的 H5 控件不会因合并 HTML/CSS 自动出现在原生界面。发布前须确认 controller、棋盘绘制与原生输入具有相同的连续视角语义；若需要共享契约改造，应先回流 `dev`，不能在发行冲突中复制一套实现。

## 2026-09-05 分支发行确认

维护者明确批准“先完成所有分支发行”，本轮边界是把同一稳定来源同步至五个 Git 发行分支并创建对应版本标签，不包括平台上传、提交审核、外部网站同步部署或知乎云部署。此项是对本轮发行时序的明确确认，不把未执行的宿主门禁记为通过，也不改变以后版本的默认验收要求。
