# 个人网站发行

个人网站渠道使用长期 `web` 分支，与 `xiaohongshu`、`bilibili`、`wechat` 同级。它只从稳定 `main` 接收共享版本，保留静态托管所需的最小发布边界；游戏 SemVer 与其他渠道完全一致。

## 产物与部署位置

- `npm run build:web` 先执行共享 H5 校验，再把 `app/` 完整复制到被 Git 忽略的 `dist/web/`。
- 构建产物必须以 `index.html` 为目录根，资源继续使用相对路径，因此可以部署在站点子路径。
- 个人网站仓库的固定目标是 `show/topology-gomoku/`。不要把本机绝对路径写进脚本或长期文档。
- `dist/web/` 与网站部署副本都是生成产物；前者不提交游戏仓库，后者只提交网站仓库。

## 发布流程

1. 从长期 `web` 建立 `codex/release-web-X.Y.Z` 任务分支与 worktree，再合入本轮稳定 `MAIN_SHA`。
2. 运行 `npm run check`、`npm run build:web`，确认 `dist/web/index.html` 存在且文件数与 `app/` 一致。
3. 在个人网站仓库从其稳定分支建立独立部署分支，将 `dist/web/` 同步到 `show/topology-gomoku/`。同步时删除的只能是这个固定子目录内的旧发布文件。
4. 从网站仓库根目录启动本地静态服务器，通过 `/show/topology-gomoku/` 访问；至少检查一个桌面视口和一个移动视口，并验证首页、设置、关卡进入、落子与本地进度。
5. 先交付本地预览和验证记录。用户明确确认后，分别把游戏任务分支快进合入 `web`，把网站部署分支合入网站稳定分支；随后再部署网站。

网站渠道不修改共享 UI，也不添加只为站点路径服务的资源前缀。若子路径预览失败，应修复共享的相对路径契约并从 `dev` 回流，不在部署副本里手改游戏代码。
