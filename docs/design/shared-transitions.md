# 液态玻璃共享元素转场规范

本文定义液态玻璃共享元素转场的长期设计与实现规范。它适用于关卡卡片、设置面板、收藏卡片和其他“一个玻璃元素展开为另一界面”的动画。

设计目标不是“动画很多”，而是让用户始终相信自己看到的是同一个物体：它从卡片移动、放大并成为棋盘；返回时，棋盘收束并自然交还给原卡片。运动可以灵动，但空间关系、材质和身份不能中断。

## 一句话原则

**形状由外壳负责，内容由内容层负责，Q 弹只做整体等比缩放，静态页面必须在动画撤销前已经与最后一帧完全对齐。**

## 常见问题为何容易混淆

“慢”“抖”“闪”或“形状没对上”可能分别来自时间、几何、内容、材质或生命周期。只改时长或缓动，可能暂时掩盖一个问题，同时暴露另一个问题。诊断时应先区分问题所属轨道，再选择修复方式。

| 可见现象 | 常见原因 | 判断方法 |
| --- | --- | --- |
| 打开时目录里的 UI 下沉再消失 | 页面退场还带有位移，与共享元素的移动叠加 | 固定标题、网格等非共享元素的边界，退场只改透明度 |
| 打开和收回体感速度不同 | 两个方向使用了不同的旧时长，或收回还残留额外阶段 | 分别测量“触发到静止”的实际时间，不只检查常量名 |
| 速度变快后不够 Q 弹 | 只压缩总时长或使用高阻尼单次回摆 | 用多个幅度递减的整体缩放极值表达低阻尼回弹 |
| 回弹像突然抖一下 | 每段使用强 `ease-out`，在极值处速度被硬切断 | 极值之间用连续、对称的缓动，并让幅度逐次衰减 |
| 边缘像果冻或波浪 | X/Y 使用不同的回弹比例，圆角也在各帧独立变形 | Q 弹阶段只允许统一的 `scale(s)`，圆角保持稳定 |
| 棋盘格突然位移 | 棋盘内容拥有独立的弹性位移或缩放 | 棋盘内容跟随整体；除淡入淡出外，不单独“弹” |
| 收回时棋盘被纵向拉长 | 外壳非等比缩放时，内部画布也继承了相同比例 | 外壳负责矩形形变，内容层做反向补偿以保持等比 |
| 收回时棋盘没有变小，只被边缘裁掉 | 使用 `object-fit: cover` 或仅缩小容器 | 内容使用 `contain`，同步等比缩小并在适当阶段淡出 |
| 动画末尾先变宽、再突然缩窄 | 动画终点尺寸、圆角与真实静态棋盘不一致 | 从真实元素读取最终边界和圆角，禁止凭经验写近似值 |
| 回弹后整个棋盘闪没再出现 | 动画取消后，底层 CSS 仍把真实棋盘设为透明 | 撤销动画前先保证静态样式就是最终可见状态 |
| 收回时突然消失再出现 | 过渡层已淡出，真实卡片尚未可见，形成透明度空窗 | 两层透明度必须有覆盖区，并逐帧检查总视觉覆盖度 |
| 收回开始的一瞬间闪出卡片 | 先显示目录，下一帧才隐藏目标卡片 | 切换页面前先隐藏目标共享元素 |
| 克隆卡片交接时形状跳变 | 克隆层与真实卡片的样式、内容或动画相位不完全一致 | 优先直接动画真实目标元素，减少克隆到静态的交接 |
| 玻璃边缘显得粗、像塑料框 | 边框、伪元素描边和多层内阴影叠加 | 只保留一条轻薄边缘与低对比高光，避免重复描边 |
| 肉眼可见闪烁，代码状态却看似正确 | 只看起止截图，没有观察交接前后相邻帧 | 记录逐帧计算样式、边界、透明度和画布尺寸 |

这类问题不能只靠修改总时长解决。时长、几何、内容、材质和生命周期是五条独立轨道，必须分别正确，再在同一时间线上汇合。

## 正确的分层模型

共享元素转场至少分为三层：

1. **页面层**：目录页与游戏页。只负责可见性和交互状态，不参与共享元素的弹性形变。
2. **玻璃外壳层**：负责位置、外部尺寸、圆角、边缘高光和阴影，是“卡片变棋盘”的几何主体。
3. **内容层**：关卡图案或棋盘画面。负责等比缩放、淡入淡出和轻微清晰度变化，不承担外壳的非等比形变。

这个分层解决了一个关键矛盾：卡片和棋盘的宽高比可能不同，外壳必须非等比变化才能精确落位，但棋盘格不能跟着拉伸。外壳的非等比 `scaleX/scaleY` 仅用于几何映射；内容层使用反向补偿，保持视觉上的统一比例。

设外壳从棋盘缩到卡片所需比例为：

```text
scaleX = cardWidth / boardWidth
scaleY = cardHeight / boardHeight
uniformScale = min(scaleX, scaleY)

contentScaleX = uniformScale / scaleX
contentScaleY = uniformScale / scaleY
```

这样外壳可以精确变成目标矩形，而棋盘内容仍然保持正方形，并随整体缩小后淡出。

## 打开：卡片成为棋盘

打开需要有表现力，但不能让用户觉得棋盘是一块软胶。

### 推荐节奏

关卡入口的基线总时长为 `300 ms`：

- 前段快速完成主要位移和尺寸展开。
- 中后段做整体等比回弹。
- 经过同视口验收的缩放极值是 `1.068 → 0.962 → 1.028 → 0.988 → 1`，对应偏移约为 `46% → 64% → 80% → 92% → 100%`。
- 极值间使用连续、近似对称的 ease-in-out，不在每个拐点突然刹停。
- X/Y 比例必须相同；内容不得拥有另一组弹性关键帧。

这些数值是关卡入口的实现基线，不是所有组件都必须照抄的固定参数。需要调节时，优先保持以下关系：第一次越界明显、第二次反向越界较小、后续幅度单调衰减、最后精确到 `scale(1)`。

### 打开时的状态顺序

```text
读取源卡片与最终棋盘的真实边界
→ 游戏页以最终布局建立，棋盘静态终态已经正确
→ 棋盘从源卡片几何位置开始执行共享元素动画
→ 目录页仅原地淡出，不发生下沉或缩放
→ 动画停在精确终态
→ 静态棋盘保持可见
→ 同一绘制节奏内取消临时动画状态
```

最重要的是最后三步。动画 `fill: forwards` 不是永久样式；调用 `cancel()` 后浏览器会立即回到底层 CSS。底层 CSS 若仍是 `opacity: 0`、不同圆角或不同 transform，用户就会看到一帧闪烁或跳变。

## 收回：棋盘交还给卡片

收回不是简单把打开动画倒放。视觉语言要一致，但信息目标不同：打开是在建立场景，允许明显回弹；收回是在结束场景，应更快、更直接，避免用户等待。

### 推荐节奏

关卡返回的基线总时长为 `240 ms`：

- 外壳沿单调路径缩到目标卡片，不做多次来回振荡。
- 棋盘画面等比缩小并逐渐淡化，避免在狭窄卡片内被裁切。
- 真实目标卡片在外壳完全消失前淡入，二者有受控的覆盖期。
- 弹性表达主要留给打开；收回的“灵动”来自快速而连续的聚拢，不来自抖动。

“可逆”在这里指对象身份、路径、端点和因果关系可逆，并不要求两个方向机械地使用同一条时间曲线。两个方向都必须快速且连续，但收回可以比打开更短。

### 收回时的状态顺序

```text
冻结当前棋盘画面和最终棋盘边界
→ 找到真实目标卡片
→ 在目录显示之前隐藏真实目标卡片
→ 显示目录页，并建立棋盘过渡外壳
→ 外壳变到卡片的精确边界；棋盘内容等比缩小并淡出
→ 真实卡片在过渡外壳仍有覆盖时淡入
→ 真实卡片已处于最终静态样式
→ 取消真实卡片动画
→ 下一绘制帧移除过渡外壳
→ 恢复交互
```

这里的顺序不能随意交换：

- 如果“显示目录”早于“隐藏真实卡片”，收回开始会闪出一次卡片。
- 如果“移除过渡外壳”早于“真实卡片可见”，中间会出现空白帧。
- 如果先取消真实卡片动画、再补静态可见类，卡片会短暂回到隐藏状态。
- 如果同一帧同时更换多个层而没有稳定底图，合成器可能暴露中间状态。

## 几何连续性的硬约束

动画的第一帧和最后一帧都必须来自真实元素，而不是目测估算。

- 用 `getBoundingClientRect()` 读取源和目标的真实位置与尺寸。
- 从计算样式读取圆角。外壳做非等比缩放时，要补偿圆角，使变换后的视觉半径等于目标卡片半径。
- 不要同时动画 `left/top/width/height` 和 `transform`。固定过渡层基准矩形，只动画合成器友好的 `transform`、`opacity`，必要时少量使用 `filter`。
- 棋盘画布的 CSS 尺寸和 backing store 应在动画前稳定；不要让页面布局动画触发中途重算或重建画布。
- 共享元素的最终 `transform`、`opacity`、`filter`、圆角和边界必须与静态元素逐项相等。

任何“先放大成更宽的形状，然后末帧突然缩窄”的现象，本质上都是动画终点与静态终点不是同一个几何状态，而不是回弹幅度不够。

## Q 弹应该作用在哪里

### 应该做

- 把棋盘和玻璃边缘视为一个刚性整体，使用统一的 `scale(s)`。
- 用多个幅度递减的极值表达低阻尼弹簧。
- 保持位移、缩放和透明度各自职责清楚。
- 在速度较快的前提下，让极值间的速度连续。

### 不应该做

- 不要用 `scaleX` 与 `scaleY` 的交替拉扯来表达 Q 弹。
- 不要让圆角四个角分别波动。
- 不要让棋盘格子相对外壳独立位移或反弹。
- 不要用一次很小、很急的末端抖动冒充弹性。
- 不要把材质高光、边框和阴影也做成明显呼吸或相位不同的动画。

非等比缩放只允许出现在“外壳从棋盘矩形映射到卡片矩形”的几何轨道里，不能混入弹性轨道。两者概念必须分开。

## 液态玻璃材质的约束

液态玻璃的“液态”主要来自连续的光学变化和有生命力的整体运动，不等于边缘像果冻一样摆动。

- 边缘以单条、低对比、半透明的 1 px 轮廓为基线。
- 高光、内阴影和色散要克制，避免多层描边叠成粗白边。
- 保留背景信息，避免高不透明白色填充把玻璃做成塑料板。
- 外壳和过渡层使用一致的透明度、模糊、饱和度和阴影语言。
- 运动时允许轻微亮度或饱和度变化，但不得在最后一帧突然切换材质。

如果静态棋盘的边缘和过渡外壳不是同一套材质，即使几何完全对齐，交接时也会被感知为闪烁。

## 透明度交接规则

“棋盘淡出、真实卡片淡入”本身没有问题，问题通常出在交接流程。

- 源层与目标层必须有覆盖区，不能一层先归零、另一层稍后才出现。
- 不要只看两层各自的 opacity 曲线；要观察合成后的最低视觉覆盖度。
- 优先动画真实目标元素，避免复制层与真实元素在字体、伪元素、图片加载、动画相位或像素舍入上的差异。
- 必须使用克隆时，克隆的尺寸、圆角、内容、材质和动画状态都要冻结，并采用“真实层先稳定，克隆层后移除”的交接顺序。
- 过渡层淡出后仍可以短暂保留在 DOM 中，等待真实层完成一次稳定绘制，再移除。

## 不要靠肉眼猜：逐帧验收清单

视觉验收必须在同一视口、同一页面状态下覆盖打开和收回两个方向。

### 录制或采样的关键帧

- 打开前静态卡片。
- 打开主要位移结束时。
- 每个明显回弹极值。
- 动画完成前一帧、完成帧、取消动画后一帧。
- 收回触发前。
- 收回中段，棋盘内容仍可辨认时。
- 过渡层与真实卡片交叠时。
- 过渡层移除前一帧与移除后一帧。

### 每帧需要记录

- 源、过渡层和目标元素的 `getBoundingClientRect()`。
- `opacity`、`transform`、`border-radius`、`filter`、`visibility` 和 `display`。
- 棋盘画布的 CSS 尺寸与 backing store 尺寸。
- 目标卡片是否已被隐藏、是否已进入静态可见状态。
- 页面容器是否发生了不应有的位移或缩放。
- 两层交接期间是否出现视觉覆盖度接近零的帧。

### 必须回答的问题

- 非共享 UI 是否始终停在原位置？
- 棋盘格是否一直保持正方形和相对位置稳定？
- Q 弹是否是整个棋盘统一缩放，而不是边缘或内容单独形变？
- 最后一帧与静态画面的边界、圆角、材质是否完全一致？
- 取消 Web Animation 后，计算样式是否仍与取消前相同？
- 快速连续打开/返回时，旧动画和临时类是否被正确清理？
- `prefers-reduced-motion` 下是否能直接、稳定地完成交接？
- 控制台是否没有异常，交互是否在动画完成后恢复？

## 自动化回归应守住什么

单元测试无法判断“够不够 Q 弹”，但可以阻止已确认的结构性错误回归：

- 目录退场不得包含位移。
- 打开与收回的时长常量和关键阶段必须明确。
- 打开回弹不得出现 X/Y 不同的弹性比例。
- 收回外壳必须使用目标卡片的真实边界与圆角。
- 棋盘内容必须使用 `object-fit: contain` 和比例补偿。
- 目标卡片必须在目录显示前进入隐藏状态。
- 真实卡片必须在临时动画取消前进入稳定可见状态。
- 底层 CSS 不得在共享元素交接期间把真实棋盘设为透明。
- 临时动画层必须在稳定绘制后才移除。

自动化测试负责锁定结构，逐帧同视口 QA 负责判断节奏、材质和连续性。二者不能互相替代。

## 调参顺序

动效调参应按以下顺序进行，避免在错误架构上反复调整参数：

1. **先校准静态端点**：源和目标的边界、圆角、材质完全一致。
2. **再校准生命周期**：目标何时隐藏、何时可见、动画何时取消、临时层何时移除。
3. **再处理内容比例**：画布是否等比、是否裁切、是否需要反向补偿。
4. **再处理路径**：页面是否稳定，外壳是否只使用 transform 移动。
5. **最后才调手感**：总时长、回弹幅度、阻尼和透明度节奏。

如果端点和交接还会闪，继续调 easing 没有意义；如果内容还在拉伸，继续增加回弹只会让问题更明显。

## 关卡卡片与棋盘的实现基线

关卡共享元素实现位于 `app/assets/game.js` 的 `animateCardIntoBoard`、`animateBoardBackToCard`，材质和过渡状态位于 `app/assets/style.css`。

- 打开：`300 ms`，快速展开后做统一、低阻尼、幅度递减的整体缩放回弹。
- 收回：`240 ms`，单调缩到目标卡片；外壳精确变形，棋盘内容等比缩小并淡出。
- 页面：目录原地淡出，不再下沉；游戏页不执行会改变棋盘布局的额外几何过渡。
- 交接：打开时静态棋盘先稳定再取消动画；收回时真实卡片先稳定再移除过渡层。
- 材质：薄而通透的单层边缘，避免重复描边和厚重塑料感。

这些参数以后可以随整体节奏系统调整，但上述分层、端点精确、交接无空窗和逐帧验收规则属于长期约束。

## 视觉改动的交付门槛

- 在本地预览中完成真实交互测试，不以静态截图或测试通过代替手感验收。
- 保留同视口的打开前、中间态、打开后、收回中间态和收回后证据。
- 本地预览尚未完成视觉验收前，不合并到 `dev`，也不删除功能分支或 worktree。
- 合并前运行仓库规定的测试、校验与差异检查，只提交本任务范围内的文件。

视觉动效必须经过“实现—逐帧检查—本地预览—视觉验收”的完整闭环。测试通过只能证明结构没有明显回归，不能替代对速度、连续性、材质和情绪的判断。
