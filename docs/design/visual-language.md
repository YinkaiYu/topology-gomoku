# 视觉设计语言

本文是拓扑五子棋跨页面、跨功能和跨平台的长期视觉基线。单次设计稿、截图或平台默认样式不能覆盖这些原则。

## 整体气质

整体气质是**简约、典雅、克制**。

- 以留白、比例、字体、清晰层级和少量语义色建立秩序。
- 避免装饰堆叠、无意义渐变、过多强调色、厚重阴影和与既有界面无关的新风格。
- 同类控件复用颜色、圆角、描边、阴影、间距、字体层级和动效节奏。
- 每个视觉效果都要服务于状态、层级或交互反馈；不能解释其作用时，优先删除。
- 新页面不能形成孤立的视觉方言；平台适配可以尊重宿主习惯，但仍需保持品牌气质与核心交互的一致性。

## 新控件的设计判断

先问它帮助玩家完成什么，再决定它需要多少视觉重量。增加一种能力，不意味着需要增加一块面板。

- **主次先于装饰**：棋盘是主体，辅助工具融入留白。液态玻璃是可复用的材质语言，不是要求每个图标外面都包一层玻璃；无底板工具按钮同样属于设计系统。
- **复用先于重画**：从稳定基线查找承担相同语义的图标和组件，同时比较静止、按压、拖动、释放与禁用状态。复用名称或颜色不等于复用交互契约。
- **一个信息只承担必要角色**：两端按钮既标注目标又提供快捷切换，滑块表达连续进度时，不再叠加重复的二维／三维状态胶囊。
- **可见尺寸与可操作面积分离**：细轨道、小图标可以克制，但不能以缩小触摸区域或去掉键盘能力为代价。
- **以结构建立秩序**：相关操作共用列中心、行高和间距；时间导航按“后退 — 当前模式 — 前进”安排。减少按钮后重新检查整体栅格，不留下旧布局的空洞，也不靠逐个偏移像素对齐。

手感参照必须指定到同一产品中的具体控件和交互状态，例如设置面板滑块的按压折射与点击滑行，而不是笼统要求“像玻璃”。比较形变、位移、停靠与底层内容如何被透射；不能仅凭圆角、高光和模糊判定材质一致。

## 液态玻璃

液态玻璃是卡片、按钮、滑块、开关、状态胶囊和浮层共享的材质系统，而不是单个组件的特效。

- **静止态**：底色通透，保留背景信息，以轻微边缘光和克制阴影区分层级。
- **按下态**：控件向外鼓起，折射增强但文字仍可辨；不通过整体缩小模拟按压。
- **拖动态**：形变、位移和折射连续，轨道与内容层关系稳定，不出现跳帧、重影或硬切。
- **释放态**：回到准确停靠点，允许短促且受控的回弹；不能残留高光、错位或重复图像。
- **禁止样式**：大面积乳白磨砂、硬色带、过强彩边、镜面高亮、塑料质感和孤立的拟物组件。

## 色彩与层级

- 中性色承担大部分结构，强调色只表达选择、进度、风险或下一步行动。
- 同一屏内避免多个互相竞争的高对比区域。
- 阴影、描边和模糊用于说明空间层级，不作为装饰填充。
- 棋盘、拓扑曲面与交互控件必须保持主次关系，不能让材质效果压过玩法内容。

球面“归圆”的边界配色按实际粘合关系分组：上边与左边使用青绿色，右边与下边使用金黄色。二维辅助线、展开到曲面的动画以及曲面边线沿用同一组对应关系。

有拓扑连接的棋盘边，其辅助线位于最外排落子点之外半格，网格线延伸至辅助线；两侧各半格共同表达跨界相邻点之间的一格距离。开放边维持原有网格范围。边界提示与二维／三维转换保持连续，落子点、命中位置和规则不因边界外移而改变。

棋盘三维视图采用随展开程度渐入的透视，曲面与棋子共同表现近大远小。曲面保留纸色材质，以实际前后遮挡区分网格、边界、棋子与连线；环孔保持可见，交叠曲面遮住后方内容。棋子经过轮廓时逐部分显露，落子命中与可见表面保持一致。二维落点和目录图案的投影不随此变化。

## 字体与文案

- 应用中文统一使用内嵌 `Topo Serif`，不得把系统字体回退当作正常结果。
- 标题、正文、标签、状态和数字层级应沿用已有字号、字重和行高节奏。
- 文案保持短、准、自然，避免为了“有设计感”使用难懂术语。
- 优先不展示没有必要的信息，而不只是把注释缩短。重复状态、等待占位、持续可见的操作解释会分散注意力；没有即时决策价值时应删除或放入按需打开的详情。
- 首页标题保留“拓扑 / 五子棋”两行左对齐，采用 1.2 倍行高，常规字号为 46–62 px，紧凑高度为 40–52 px。标题与右侧品牌图标整体垂直居中后，向下微调 4 px 作视觉校正；不附加宣传口号，标题区与旅程列表之间保留原有层级和留白。
- HTML、JavaScript、Canvas、JSON 与 CSS `content` 中的用户可见文本都属于字体覆盖范围。
- 修改文案后运行 `npm test`；缺字时运行 `npm run fonts:subset`，并保持字体与样式表 URL 直接引用无查询参数或片段的包内真实文件名；缓存失效由统一包版本和平台发布清单管理。

## Arena 观战界面

本节只适用于独立 Arena 渠道。观众的注意力应落在棋盘、棋手随想，以及主动开启的解说上。发言使用通透、带克制阴影的悬浮聊天气泡，与背景形成明确层次；姓名和棋色标识归属；每条气泡上方以低对比度标记“第 N 手”，未落子时标记“开局”，实际发送时间可在时间线查看。没有发言时保持留白，不展示解释性占位。双方消息按聊天顺序由底部向上推进，新消息从底部入场；查看历史时不抢走滚动位置。显示名称和头像可配置，头像与姓名放在聊天气泡外侧，黑方在左、白方在右，靠近最新发言，不在顶部另设身份栏；头像旁不再重复叠加棋色标记；棋色由顶部棋钟旁较大的黑白棋子表达，不叠加绿色回合点或常驻连接指示点。

首页复用原游戏大 logo 和标题字形，logo 在上、单行“拓扑五子棋”在下，整体在左侧区域垂直居中，不叠加本地模式副标题或关卡大图。对局只居中显示关卡名称和图案，不显示棋局名称和左上角品牌。设置复用原游戏滑杆式图标，首页放在“开一局棋”面板右上角，对局放在关卡名旁边；管理、邀请、棋手资料与记录收进设置，底部不再另设入口。棋局状态、手数和复盘返回操作共用固定高度的一行，不能触发棋盘和双方身份的位置变化。

解说默认关闭，关闭时整个区域移出布局，不保留空洞。主动邀请后才出现解说区域；发言不应遮住棋盘。只面向横屏桌面浏览器，以 16:9、4:3 检查比例、气泡可读性与棋盘空间，不为移动端追加独立布局。

准备阶段复用棋盘下方的状态行，区分等待入席、双方准备与等待某方就绪。设置中按席位显示“未入席 / 准备中 / 已就绪”，开赛后收起；不在聊天头像旁增加常驻标记或说明卡片。新棋局双方入席后，状态行显示统一准备倒计时；双方提前就绪或倒计时结束自动开始。浏览器保留暂停、继续和结束操作，违规判负放在设置的管理操作中，经确认后生效。

工具使用模式在开局面板通过同一液态分段控件选择，使用“仅允许推理”和“允许自制工具/引擎”两档，分别标记准备 1 分钟和 5 分钟，模式切换保持固定布局。

棋钟在开局面板直接选择，三档限时与不限时沿用分段选择控件，标明分钟与加秒单位，切换时面板布局固定。棋盘尺寸使用直接编辑的输入框，错误反馈沿用页面样式。控件通过可见标签和无障碍名称说明用途，详细发言时间归入时间线。棋局记录在列表内呈现胜负结果，沿用既有字体层级。

液态换挡、连续滑条和尺寸输入通过选中档位、玻璃材质与文本插入光标表达当前状态。焦点边框统一关闭，控件保留 Tab 导航、方向键操作和直接编辑能力。

邀请弹窗聚焦角色标题、参赛提示词和复制操作。结束棋局的确认使用标题与操作按钮，删除和清空记录的确认保留简短的数据后果说明。提示词框、名称输入框与其他可聚焦元素同样采用统一的无外框焦点样式。

提示词框、弹窗内容和解说区使用统一的细窄滚动条，轨道透明，滑块采用低对比度圆角样式，滚动区域延续面板的通透材质。

状态文字以独立文本块和统一间距排列。棋局底部的手数与状态、记录列表的关卡与棋手、结果与原因，以及时间线的时间与角色使用同一分组方式。

首页配置面板和弹窗沿用 `main@3977ba0` 的 `app/assets/style.css` 中 `.settings-sheet::before/::after` 材质。外层使用原有边缘渐变，内层与边缘相隔 1.5 px，使用原有低透明度底色、内沿光和受控透射。弹窗背景沿用 `.scrim` 的轻遮罩，棋盘透过面板仍能辨认。换挡控件沿用游戏本体的透明滑块、档位吸附与回弹，拖动时透射的轨道和标签与实际位置对齐。

新随想到来时，共同时间轴中已有消息、头像和手数标记平滑上移，新消息由底部进入。连发时从当前画面位置接续，边缘淡出按移动后的实时位置更新。用户翻阅历史时保持阅读锚点，滚动操作可以打断动画。减少动态效果时直接呈现最终位置。

双方随想共用同一聊天时间轴，黑白消息按事件顺序交错，滚动时同步移动；头像随各自的气泡排列在外侧。气泡随内容自然增高，不设置内部滚动区域，不出现横向滚动条；较长的旧消息完整换行。接近聊天区上下两端时，按整条消息的位置降低气泡和头像的统一透明度，不给单个气泡内部加渐变或遮罩；棋盘本身保持清晰。气泡底色与描边沿同一闭合轮廓绘制，尾角从边框连续突出，不叠加独立图形；白方为黑方的水平镜像。棋钟位于顶部左右两侧，分别对应黑白方，关卡名称居中；倒计时采用等宽数字，不改变布局；走钟方数字清晰、冒号轻微呼吸，停钟方数字变浅，换钟时做一次克制的缩放强调。当前行棋方可显示短三点等待气泡，随换手切换，暂停、终局、复盘或观战连接中断时收起；它只表示等待落子，不代表已检测到模型正在推理，不保存为棋手消息。减少动态效果时保留静态提示和明暗层级。棋盘下方将状态与手数合为一处，放在两条滑块上方，例如将“第 8 手”和“已暂停”并排显示；终局结果也在此显示，不另设状态栏，不在设置中重复。回看时同一行显示回看手数与返回操作，行高不变，屏幕阅读器仍可获得状态更新。底部状态文字为 15 px，滑块端点复用游戏本体 20 px 线性图标及下方标签；状态行与两条滑块共用 44 px 行高、4 px 行间距，保持中心等距。两条滑块共用等宽的加长轨道、端点列与滑块尺寸，控件区随棋盘列展开，最大宽度 560 px。观战轴标采用 14–16 px、左下角 A1、字母向右、数字向上；已连接边的网格延伸半格到辅助线，开放边不延伸。

## 状态连续性

用户看到的是连续变化的同一个对象，不是实现中的多个独立模式。连续性需要同时覆盖几何、材质、布局、输入和异步任务。

- **接续真实状态，而非目标状态**：开始新动画前，捕获当前实际展示的进度、姿态与尚未结束的弹性。不能把中间态按阈值归成两个端点，也不能从上一次点击的目标值重新开始。
- **进度一致仍不够**：映射、投影、坐标基底或曲面参数化改变时，即使进度不变也可能发生位置跳变。应比较交接前后的实际几何，保持棋子附着与接缝连续；必要时让新映射从恒等映射逐步进入。
- **显示与控制同源**：画面和滑块共用实际进度，避免各自的缓动时钟产生脱节。点击滑行可以被重新抓取，反向拖动不能先跳到旧目标；减少动态效果时直接到达同一个有效终点并释放状态。
- **暂时隐藏不等于删除空间**：教学、演示或自动动画暂时不提供操作时，内容可隐藏，行高与相邻控件锚点仍稳定。先确定状态再显示页面，避免首帧闪现；保留占位时同时处理点击、焦点和无障碍状态。只有该上下文本就不提供此功能时才移出布局。
- **锁定覆盖整段操作**：无效按下不能在解锁后的松手时变成有效操作；长按、旋转与点击应明确区分。AI、计时器和用户输入遵循同一忙碌边界，恢复后不重复、不遗漏。
- **中断也是正常路径**：释放、取消、丢失捕获、失焦、隐藏页面和切换关卡都要有收束策略，不能残留交互锁或让旧回调修改新棋局。

调优顺序是先保证状态与首尾交接正确，再统一布局和材质，最后调整时长与缓动。延长动画不能修复错误的起点，增加模糊也不能修复重叠的折射层。

## 动效与交互

- 首页与对局保持固定视口，不通过滚动或拖动页面补足空间。矮窗口优先调整信息排列：关卡图标与两行文字并排，文字作为整体垂直居中；保留七个入口同屏可见，不以压叠内容换取整屏。
- 首页关卡图案按卡片实际可用区域缩放，普通图案高度上限 80 px，归圆上限 100 px；空间充裕时保留终章图案的尺寸层级，不把横排卡片统一锁成小图标。拓扑标签为 11 px，关卡名为 17 px；仅在不高于 440 px 的极矮窗口使用 10 / 15 px。先回收卡片内边距并调整排列，不能让容器留白宽裕而内容过小；极矮窗口仍以完整显示和不重叠为先。
- 动效表达空间关系、状态变化或操作结果，不进行无意义的持续运动。
- 同类控件的按下、拖动、释放和禁用反馈必须一致。
- 液态滑块与开关在拖动中允许轻微柔性滞后；点击跳档或释放吸附时应按移动距离保留可感知的惯性滑行，并以一次受控回弹停靠，避免位移在前半程骤然完成或连续振荡。
- 滑块或开关的挤压、鼓起与折射增强只在指针直接命中可移动玻璃体时出现；点击轨道或其他档位只表现惯性位移，不伪造被按压的形变。
- 连续视角滑块按压时，透过玻璃看到的轨道应明显压窄；计算折射压缩时要抵消玻璃体自身的鼓起放大。玻璃下方的未折射轨道须局部遮掉，只保留与真实轨道同源、随滑块位置连续对齐的折射层，不能用两条轨道叠加冒充透射，也不靠磨砂底板遮盖。
- 同一液态控件可以按实际输入类型调整质量感：触摸与手写笔输入允许比鼠标、键盘更长的跟随和吸附时间，但停靠点、形变幅度和回弹次数保持一致。
- 共享元素转场保持对象身份连续；首尾状态准确比中段夸张更重要。
- 棋盘视角使用无外围面板的“二维按钮 — 细轨道与独立玻璃滑块 — 三维按钮”，保留至少 44 px 高的交互区。两端复用下排工具按钮的线性图标、上图下字与字号，不使用玻璃底板、边框或选中底色，只以颜色区分当前端点。引导期间隐藏内容但保留位置。滑块与曲面共用逐帧进度，点击轨道与两端按钮使用同一惯性节奏；终局自动展示时同步显示进度但禁用输入。
- 视角记忆保留最终朝向，二维／三维切换不重播拖动经过的整圈。只在完整二维或三维端点规范等价角度，半展开时的拖动与中途反向切换保持连续；终局姿态转换也采用短角路径。
- 从对局接入终局展示时，必须继承实际展开程度、旋转与弹性形态；球面的共形网格调整从恒等映射连续过渡到目标映射，不在第一帧替换参数化。过渡中接缝和棋子附着关系保持不变。
- 终局复盘行保持“上一步 — 复盘／定局 — 下一步”的顺序，复盘开关居中；DOM 与键盘焦点顺序必须和视觉顺序一致，不依赖 CSS 调序。
- 视角行、复盘行与底部工具行共用等宽三列、列间距、行高与纵向间距：左列为“二维／上一步／旅程”，右列为“三维／下一步／下一关”。滑轨填充两端按钮之间的空间，不单独限宽或改变端点列中心；引导占位沿用同一行高。
- 触摸反馈要跟手，回弹短促，避免过冲、振荡和妨碍阅读的折射。

共享元素的分层、几何与交接规则见 [`shared-transitions.md`](shared-transitions.md)；视觉修改的证据要求和验收流程见 [`qa.md`](qa.md)。
