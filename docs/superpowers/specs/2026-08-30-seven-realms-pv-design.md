# 《拓扑五子棋》章节预告 PV—「足迹回环」设计规格

## 状态

- 设计已于 2026-08-30 与项目所有者完成讨论并确认。
- 本文只确定创意、叙事、视听和工程边界；实施计划、依赖安装与视频制作在本文通过审阅后另行开展。
- 参考作品为《原神·提瓦特篇》主线章节预告 PV「足迹」。本项目借鉴其章节预告、宣告式旁白和音乐换章结构，不复用其镜头、画面、角色、音乐、音效、字体装饰或具体文句。

## 目标

制作一条面向新玩家的横版宣传 PV，让观众在一条完整旅程中理解《拓扑五子棋》的核心吸引力：熟悉的五子棋会因空间的连接方式而产生七套不同规则。

成片需要同时做到：

1. 具有庄重、电影化、带少量科学幻想的章节预告气质；
2. 真实展示游戏中的边界辅助线、跨界落子和通关流形，不用虚构界面代替玩法；
3. 让平面、圆柱面、环面、莫比乌斯环、克莱因瓶、实射影平面和球面拥有清晰、彼此不同的视觉与音乐身份；
4. 延续游戏简约、典雅、克制的品牌语言，不用堆叠装饰制造宏大感；
5. 建立可复现、可预览、可逐帧验证的 HyperFrames 源工程。

## 交付范围

- 16:9、4K、60fps 成片；
- 48kHz 立体声混音；
- HyperFrames 源工程、旁白文本、字幕时间信息、原创音乐工程与分轨、资产清单和授权记录；
- 关键帧联系表与完整 QA 记录。

最初节奏蓝图预计约 160–165 秒；当前已批准的 F `cold-witness` 正式旁白按自然中文语速把确定性时间线扩展为 214.040 秒，后续表格仍作为镜头顺序与相对节奏参考，不代表当前绝对时间。时间轴不是逐秒硬约束；最终长度可以随配音语气、音乐乐句、镜头运动和黑场呼吸自然调整。

## 叙事与旁白

`ACT.`、章节名和流形名只出现在章节牌的两阶段显影中，不进入旁白音轨。

这里禁止的是把章节牌两阶段标题作为报幕词播报；它不删除定稿正文中自然出现的同名词。比如「方庭以有限的秩序收容第一条五连」是已批准旁白，必须逐字保留，不能因为「方庭」也是章节名而删改或另作标题朗读。

旁白采用成熟、沉静、克制、略带宿命感的男声。先以高质量合成音完成节奏版；若中文语气、咬字或情绪不足，再替换为真人配音。配音不得用刻意压低、过度气声或拖长尾音伪造史诗感。

定稿旁白如下：

> 人们总把棋盘的边缘视作尽头。
>
> 可那些消失在边界上的道路并未中断。它们在另一处接缝后延续，将遥远的落点重新变为近邻。
>
> 现在，落子之人啊，循着隐藏的连接前行吧。七种世界，将在你面前依次展开。

### ACT. PROLOGUE / 方庭 → 平面 / 方庭

> 边界分明，方向笔直，胜负都在眼前。方庭以有限的秩序收容第一条五连，也由此埋下对所有边界的疑问。

### ACT. I / 回廊 → 圆柱面 / 回廊

> 左右相接，上下仍被截断。横向的路绕过世界回到身后，纵向的路却有始有终。
>
> 只拥有一重循环的世界，该如何丈量远近？

### ACT. II / 环游 → 环面 / 环游

> 四边相接，两个方向各自成环。一条斜线可以先越过上边，再从左侧归来。
>
> 两重循环交织之处，最短的道路往往藏在视野之外。

### ACT. III / 扭带 → 莫比乌斯环 / 扭带

> 左右边界相接，却带着一次翻转。沿同一面环行一周，归来时上下已经交换。
>
> 只有一面的世界，正反又该如何分辨？

### ACT. IV / 瓶界 → 克莱因瓶 / 瓶界

> 一组边界如圆环般相接，另一组边界让方向翻转。两种归来共处一界：一条路保持原样，一条路带回倒影。
>
> 路径会记住你选择的环绕。

### ACT. V / 双生 → 实射影平面 / 双生

> 上下左右，全都通向各自的倒影。一次越界改变方向，两次倒映使棋路重新吻合。
>
> 在双生的世界里，每次远行，都会遇见另一个自己。

### ACT. VI / 归圆 → 球面 / 归圆

> 在最后的世界，棋路离开一条边，便会沿相邻的方向继续。四条边依次归向彼此，方形的棋盘也随之闭合成球。
>
> 人们为了看清完整的世界，将它展开成一张有边的图。
>
> 所谓边界，或许只是观察世界时留下的痕迹。

章节之后不设置“七界显现”或“终章”等额外章节标题。结尾旁白为：

> 现在，落子之人。
>
> 七种世界已经显现，但最后的连接，仍等待你亲手完成。
>
> 若你已经理解边界的意义，就落下那颗棋子。
>
> 然后，去看见世界本来的样子吧。

## 字幕

- 字幕始终只占一行。较长句子按完整语义拆成连续的单行字幕，不通过压缩字号或字距强行塞入一行。
- 字幕使用现有 `Topo Serif`，白色文字、黑色描边；不使用底板、胶囊、玻璃、投影、发光或逐字高亮。
- 字幕画面省略句号。问号等承担实际语气的标点可以保留。
- 4K 母版的初始字号为 88px，实际范围为 84–96px；字幕位于底部安全区内，保持统一基线和足够左右留白。
- 字幕按语义整体淡入淡出，不逐字动画。默认使用 6–8 帧的克制过渡，最终时长服从配音。
- 章节牌期间无旁白、无字幕。

## 章节牌

章节牌采用两级视觉层级、两阶段显影。上层是一个固定槽位，下层关卡名是贯穿全程的视觉锚点：

```text
阶段 A
ACT. III
扭带

阶段 B
莫比乌斯环
扭带
```

- `ACT.` 与罗马数字位于同一行，不在罗马数字后增加句号。
- 阶段 A 只显示上层 `ACT.` 行与下层关卡名；阶段 B 在同一上层槽位把 `ACT.` 行切换为流形名，下层关卡名的位置、透明度和字号保持不变。
- 两行作为一个整体沿画面水平中心轴居中；上层槽位、`ACT.`、流形名和下层关卡名的几何中心都落在画布 50% 处，文字使用居中对齐，切换前后不得偏移。
- 上层只做短交叉淡化与轻微焦点过渡，不横向滑动、不擦除、不扫光、不逐字、不弹跳；`ACT.` 与流形名不得在任何时刻同时完整可见。
- 两个阅读阶段和中间切换都由可调时间数据管理，并在约三秒章节牌内保留清楚的阅读停留。
- 关卡名为画面主标题，流形名在阶段 B 标识空间类型；二者沿用小游戏现有“关卡名 + 类型名”的对应关系。
- 背景为近黑空间，对应流形的 SVG 轮廓作为低对比度浮雕或暗纹。
- 标题由微弱体积光和雾中显影出现，保持稳定，不做弹跳、扫光、逐字书写或夸张缩放。
- 章节牌标题只显影，不播报，也不显示字幕；正文自然出现的同词仍按定稿旁白保留。
- 全局仍以暖白、青绿和铜金为基础；章节只通过光色倾向建立区别：方庭暖白、回廊青绿、环游深蓝、扭带琥珀、瓶界铜金、双生冷紫、归圆白金。

## 转场与摄影

转场不使用跨屏连接线、页面滑动、擦除或其他演示文稿式效果。每章结束时，真实棋局停在代表性跨界五连上，棋盘在镜头前弯曲成对应流形。摄像机继续靠近，直到曲面、阴影或流形内部完全覆盖画面；短黑场与音乐换章后，章节牌从暗处显现。下一章通过相近轮廓、运动方向或明暗关系完成 match cut。

示例包括：圆柱截面匹配环面内环，环面内环匹配莫比乌斯带的扭转中心，莫比乌斯曲面掠镜匹配克莱因瓶交叉曲面。转场必须依赖真实空间和镜头惯性，不依赖装饰性线条。

PV 为离线预渲染，不受实机帧率和移动设备性能约束。可以使用高密度曲面、离线抗锯齿、体积光、景深、运动模糊、粒子、曲面折射和更复杂的灯光，但所有效果仍需服从简约、典雅、克制的视觉基线。技术复杂度不能成为堆叠特效的理由。

## 原创音乐与声音

配乐是叙事主体之一，不作为循环背景垫乐处理。Task 9 的获批作曲裁决以七个独立音乐世界取代早期“同一五音主题的七种变奏”概念：D–F–G–A–C 只在序幕形成短促结构细胞，并在 gallery / outro 可追踪回归；章节之间仅允许不超过 625 ms 的 D/A 边界音响承担衔接，不把七章旋律伪装成同源变形。

- 序幕：稀疏钢琴、低音提琴泛音、低频空气纹理，以 D–F–G–A–C 建立结构记忆；
- 方庭：D Lydian 的钢琴清亮主题与室内弦乐表现稳定、边界清晰的秩序；
- 回廊：B-flat Mixolydian 的低音单簧管、拨弦与横向循环表现一重周期；
- 环游：钢琴与钢片琴的 4.75 / 5.25 秒周期交织，形成彼此咬合的两套循环；
- 扭带：C octatonic、3+2+3/8、viola / bass clarinet 与反向弓纹理表现折返；
- 瓶界：D Phrygian dominant 的高低声部对答与金属推进增加重量；
- 双生：E Lydian 的 celesta、玻璃点、弱合唱和冷色弦乐形成镜像空间；
- 归圆：D major 钢琴、完整弦乐、克制圆号与轻合唱完成全片和声释放；
- 片尾：收束各章残影并保留 D6/9 尾音和空间残响，为标题与研究所 Logo 留出静默重量。

音乐工程需要保留钢琴、弦乐、低频、合唱氛围和音效等独立分轨，并记录所有音源、采样和许可。只使用原创旋律以及授权明确、允许视频发行的乐器音源。

当前没有可调用的 ChatGPT 插件能够可靠完成原创编曲与配器；Spotify、Apple Music 等内容插件不适合这一任务。实施阶段优先建立本地、可复现的音乐制作工具链。若后续出现合适插件，必须先核对其导出能力、商用许可和可复现性，再决定是否接入；不为使用插件而牺牲音乐质量。

音效包括真实落子、跨缝提示、曲面弯曲、空间遮蔽和章节换章低频。音效不能覆盖旁白，也不能用持续轰鸣代替音乐张力。

## 视觉身份

HyperFrames 工程必须在编写任何合成 HTML 前创建 `video/footsteps-return/DESIGN.md`。该文件继承 [`../../design/visual-language.md`](../../design/visual-language.md) 的简约、典雅、克制原则，并补充 PV 专属颜色、字体、章节光色、摄影、运动和禁止事项。

片头不出现中国科学院物理研究所标识，以保持沉浸。片尾呈现「拓扑五子棋」和较醒目的中国科学院物理研究所 Logo；不添加下载二维码、平台按钮或版本号。

## 工程结构

计划中的工程目录为：

```text
video/footsteps-return/
  DESIGN.md
  index.html
  compositions/
    intro.html
    chapter-titles.html
    chapters/
    seven-worlds.html
    end-card.html
  assets/
    topology/
    brand/
    fonts/
  audio/
    voiceover/
    score/
    sfx/
  scripts/
    verify-game-render.mjs
    build-score.mjs
  render-game.html
  src/game-render/
  renders/
```

`index.html` 只负责总时间轴和音轨编排；序幕、章节牌、七章、七界显现和片尾各自保持单一职责。`render-game.html` 以透明背景挂载未改写的真实游戏，并由 PV-only adapter 复用现有关卡、教学路径、Canvas 绘制与拓扑形变；不得重画棋盘或另造规则层。

每章使用同一个持久 iframe、Canvas 和棋局状态，由 HyperFrames 的单一单调时间线显式驱动：空棋盘建立、落子 1→5、五连停留、形变 0→1、成形停留、旋转揭示。任意 `render(state)` 都从明确基态可逆重建，因此回拖或乱序求帧不会继承历史误差。跨界落子前完整展示对应教学路径的延长呼吸线；有两次 crossing 的路径两次都展示，Klein 保持方向与翻转方向两条路径在同一实例内分别完整 1→5。教学 prompt 的 Canvas 文字调用在 PV 模式精确抑制，棋盘、棋子、连接和路径不受影响。

渲染层只在 `render(state)` 时推进；morph progress 与 rotation 独立，阶段交接不重载、不换 Canvas、不拼接素材。第五颗后的胜利线直接进入 morph=0，morph=1 直接进入 rotation=0。方庭遵守原 app：morph 为恒等变换，保持平面拓扑，抬升与倾斜只由 HyperFrames 摄影层完成；其余六章使用原生拓扑形变。透明区由 HyperFrames 绘制电影化背景，PV Canvas 禁用纸张点状纹理。

专用入口与 instrumentation 隔离在 PV 工程中；不得让制作控制、固定棋局或渲染参数进入正常玩家流程。共享源码只在确有必要且有测试覆盖时修改。

HyperFrames、音频和渲染依赖在实施计划中确定并锁定版本。新增命令、Node 版本要求、FFmpeg、字体或音乐工具后，同步更新 `package.json`、锁文件和 [`../../development/environment.md`](../../development/environment.md)。

## 失败处理与验证

构建或渲染在以下情况下必须失败并给出明确错误：缺少旁白、音乐或字体；章节总时长短于对应音轨；流形资产找不到；字幕超出安全区；章节牌缺少关卡名或流形名；输出尺寸、帧率或音频采样率错误。

每轮评审至少执行：

1. `npm test`，确认游戏规则和字体覆盖没有回归；
2. `npm run docs:check`，确认文档索引和链接有效；
3. `npm run pv:game-render:verify` 的 Chromium 透明度、确定性和阶段检查，以及 HyperFrames lint、validate 和 inspect；
4. 动画时间图检查，逐项处理冲突、死区、越界和不可见元素；
5. 序幕、七个章节牌、七章英雄帧、七界显现和片尾的关键帧联系表；
6. 4K/60fps 成片完整观看，检查字幕单行、无句号、同步、描边、黑场、运动模糊和色带；
7. 音频峰值、整体响度、旁白可懂度、声像和尾音检查。

正式渲染前先提供可热更新的 HyperFrames Studio 预览。预览确认前不得合回 `dev`。

## Git 与生成资产

源工程、脚本、设计文件、字幕、轻量音频工程和许可记录纳入 Git。逐帧图片、缓存、高码率中间文件以及 4K/60fps 成片放入忽略目录并单独交付，避免仓库膨胀。提交保持小而可回滚，设计、画面、声音和验证记录分阶段提交。
